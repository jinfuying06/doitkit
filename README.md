# 두잇킷 서비스 목업 v3.0

기업연계 수업 프로젝트의 사업제안을 설명하고 시연하기 위한 웹 목업입니다. 여러 브랜드의 행사 등록, 게임 제작, 고객 검토, 게시, 운영, 성과 공유를 하나의 흐름으로 보여줍니다.

- 현재 목업: https://doitkit-v30.jinfuying06.chatgpt.site
- 현재 저장소는 두잇킷 v3.0의 최신 수정 사항을 포함합니다. 행사 상태 다중 선택, 현재 날짜 기준 시연 일정, 운영·성과 분석, 고객 공유 미리보기를 제공합니다.
- 분석·추천·경품 발송은 시연용이며 실제 외부 서비스에 연결되지 않습니다.
- HTML, CSS, JavaScript로 구성한 정적 사이트이며 빌드나 패키지 설치가 필요하지 않습니다.

## GitHub Pages

GitHub 저장소 Settings → Pages에서 `Deploy from a branch`, `main`, `/(root)`를 선택합니다. 루트의 `index.html`이 `dist/`로 연결하며, `.nojekyll`로 빌드 없이 정적 파일을 제공합니다.

이후 main의 dist/ 파일을 업데이트하면 GitHub Pages에도 반영됩니다. 기존 ChatGPT Site는 별도로 게시해야 합니다.

## 로컬 실행

Python 3가 설치된 환경에서 저장소를 받은 뒤 아래 명령을 실행합니다.

```sh
git clone https://github.com/jinfuying06/doitkit.git
cd doitkit
python3 -m http.server 8000 --directory dist
```

브라우저에서 http://localhost:8000 을 엽니다. Windows에서 `python3` 명령이 없으면 `python` 또는 `py -3`를 사용합니다.

정적 호스팅 서비스에 배포할 때 공개 디렉터리를 `dist/`로 지정하세요. 별도 빌드 명령은 없습니다. 화면 경로는 `#home`, `#templates`, `#operate` 등의 해시 라우팅을 사용합니다. 이 GitHub 저장소에 커밋하는 것만으로 기존 ChatGPT Site가 자동 업데이트되지는 않습니다.

## 주요 화면과 흐름

| 구분 | 화면·동작 |
| --- | --- |
| 홈 | 전체 브랜드의 진행 중·예정 행사와 확인할 작업 조회 |
| 워크스페이스 | 브랜드별 행사, 브랜드 자료, 담당자 관리 |
| 게임 템플릿 | 독립적으로 템플릿 탐색, 즐겨찾기, 자연어 기반 게임 초안 생성 |
| 행사 등록 | 행사명, 브랜드, 온라인·오프라인, 날짜·시간, 유형·장소 입력 |
| 제작 | 템플릿 선택, 게임 디자인, 참여 정보·규칙, 경품·수령 설정 |
| 검토 | 고객 검토 링크, 의견과 반영 상태, 게임 확정 |
| 게시 | 행사 패스 활성화, 비용 조건 확인, 참여 링크·QR 준비 |
| 운영 | 참여 현황, 경품 잔량, 발송 실패·재발송, 일시중지·종료 |
| 성과 | 집계 확인, 요약 초안 작성, 고객 공유 리포트 공개 |
| 정산 | 추가 이용료가 발생한 종료 행사의 계산·결제 예정 정보 조회 |

행사 정보만 저장하고 템플릿을 선택하지 않아도 됩니다. 이때 제작 화면은 게임을 선택할 수 있는 빈 상태로 표시됩니다. 게임 저장은 검토 요청과 별개이며, 저장 후 검토 요청을 눌러야 검토 흐름으로 이동합니다.

## 추천 시연: 루미에르 강남 팝업 룰렛

새 행사명에 **`루미에르 강남 팝업 룰렛`**을 정확하게 입력합니다. 브랜드는 루미에르, 운영 방식은 오프라인, 유형은 팝업스토어를 선택하고 유효한 시작·종료 날짜와 시간을 입력하세요. 행사명만으로 필수 기본 정보 전체가 입력되는 것은 아닙니다. 해당 이름의 시연 설정은 게시 후 적용됩니다.

| 순서 | 조작 | 보여줄 내용 |
| --- | --- | --- |
| 1 | 홈에서 행사 만들기 → 기본 정보 입력 → 저장 | 행사 등록과 게임 선택을 분리한 흐름 |
| 2 | 룰렛 템플릿 선택 | 템플릿을 바탕으로 게임 제작 시작 |
| 3 | 게임 디자인 수정, 룰렛 칸 클릭 | 화면 요소와 룰렛 보기 직접 편집 |
| 4 | 참여 정보·동의 문구, 참여 규칙, 경품·확률·수령 방식 설정 → 저장 | 행사 운영 설정과 디자인 저장; 저장만으로 검토로 이동하지 않음 |
| 5 | 검토 요청 → 고객 검토 화면 열기 | 브랜드 담당자 이름으로 표시되는 예시 의견과 고객 검토 경험 |
| 6 | 의견 확인 및 반영, 고객 화면에서 게임 확정 | 확정 기록과 게시 준비 흐름 |
| 7 | 행사 패스·결제에서 비용 조건 확인 → 행사 패스 활성화 → 게시 | 실제 결제 없이 패스 활성화와 게시 동작 시연 |
| 8 | 운영 화면으로 이동 | 참여 21,000회, 기본 포함량 20,000회, 발송 실패 2건 |
| 9 | 실패 목록 확인 → 선택 건 재발송 | 재발송 결과와 실패 건수 감소; 재진입해도 실패를 다시 생성하지 않음 |
| 10 | 행사 종료 → 확인 | 종료 시점 이후의 확인창과 성과 화면 자동 이동 |
| 11 | 성과에서 추가 이용료 정산 내역 확인 | 1,000회 × 5원 = 5,000원, 등록 카드 끝자리 1234, 다음 달 10일 정산 예정 |
| 12 | 초안 생성 → 문장 편집·확정 → 성과 화면 공유 | 브랜드 컬러를 적용한 고객 리포트; 공개 후 수정 잠금 |

### 시연 변수와 의도

| 변수 | 값·방식 | 의도 |
| --- | --- | --- |
| 시연 행사명 | 루미에르 강남 팝업 룰렛 (정확히 일치) | 다른 행사에 영향을 주지 않고 시연 조건 적용 |
| 총 참여 | 21,000회 | 기본 포함량을 1,000회 넘는 운영 상황 표현 |
| 패스 기본 포함량 | 20,000회 | 운영·비용·정산의 공통 기준 |
| 초과 횟수 / 단가 / 추가 이용료 | 1,000회 / 1회당 5원 / 5,000원 | 초과 요금의 산정 방식 설명 |
| 발송 실패 | 게시 후 최초 2건 설정 | 실패 확인과 재발송 흐름 시연 |
| 종료 확인용 시각 | 이 행사에 한해 종료 5분 뒤인 것처럼 판단 | 날짜와 무관하게 '1시간 후 자동 종료' 전 수동 종료 확인 시연; 실제 시스템 시계는 변경하지 않음 |
| 결제 정보 | 카드 끝자리 1234, 다음 달 10일 예정 | 월 정산 안내를 보여주기 위한 가상 값 |

초과가 없는 행사에는 운영 상단의 패스 초과 안내와 추가 이용료 정산 진입을 표시하지 않습니다. 발송 실패가 있으면 해당 안내는 별도로 표시합니다. **내부 정산 정보는 고객 공유 리포트에 포함하지 않습니다.**

## 파일 구성과 수정 위치

| 경로 | 역할 |
| --- | --- |
| `dist/index.html` | 진입점, CSS·JavaScript 로드 순서 |
| `dist/app.js` | 기본 상태, 공통 함수, 기본 화면·동작 |
| `dist/create.js`, `flow.js`, `event-channels.js` | 템플릿, 브랜드, 행사 등록, 온라인·오프라인 분류 |
| `dist/studio.js`, `drafts.js`, `editor-experience.js` | 게임 편집기와 독립 게임 초안 |
| `dist/review-flow.js`, `participation-save.js` | 검토 요청·의견·확정, 참여 설정 저장 |
| `dist/navigation.js` | 뒤로가기와 이전 브랜드·행사 문맥 복원 |
| `dist/operations.js`, `event-schedule.js` | 운영 제어, 변경·종료 처리, 시간 기반 상태 |
| `dist/demo-presentation.js`, `demo-overage.js` | 강남 시연 조건, 참여량·추가 이용료·정산 |
| `dist/report-layout.js` | 리포트 구성, 공유와 공개 후 편집 잠금 |
| `dist/design.css` | 기본 디자인 변수와 DESIGN.md 기반 스타일 |
| `dist/qa-fixes.css` | 상태 박스, 버튼·필터·접근성 등 보완 스타일 |
| `checks/*.cjs` | Node.js 기반 기능 회귀 검증 |

기존 화면을 단계적으로 보완한 구조라 여러 파일이 이전 함수를 감싸거나 다시 정의합니다. 수정 전에 `index.html`의 **로드 순서와 마지막으로 적용되는 함수**를 확인하세요. 소스 파일은 `dist/`에 직접 있으며, 빌드 결과로 덮어쓰는 구조가 아닙니다. 수정 뒤 브라우저 캐시가 남으면 강력 새로고침을 하거나 `index.html`의 `?v=` 값을 갱신하세요.

## 디자인 기준

사용자가 제공한 DESIGN.md를 바탕으로 구성한 화면입니다. 원본 DESIGN.md는 이 내보내기에 포함되어 있지 않으며, 현재 구현의 변수는 `dist/design.css`에서 확인할 수 있습니다.

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `--primary` | `#ff6000` | 선택 상태, 강조 제목·건수 |
| `--primary-soft` | `#fcf4ee` | 옅은 강조 배경 |
| `--text` | `#222` | 본문·제목 |
| `--muted` | `#737373` | 설명 문구 |
| `--line` | `#e5e5e5` | 테두리·구분선 |
| `--bg`, `--surface` | `#fff` | 기본 배경 |
| `--radius` | `16px` | 패널 모서리 |

관리 화면의 공통 포인트 컬러와 고객 화면의 브랜드 컬러는 목적이 다릅니다. 고객 공유 리포트의 차트 등은 선택된 브랜드 컬러를 사용합니다.

## 데이터와 목업 범위

- 결제, 카드 청구, 초대 이메일, 경품 발송·재발송, AI 생성은 외부 서비스에 연결하지 않은 시연 동작입니다.
- 행사·검토·운영 상태는 브라우저의 실행 중 메모리로 관리합니다. 서버 데이터베이스나 사용자 계정, 여러 사용자 사이의 동기화는 없습니다. 새로고침하면 세션의 행사 상태가 초기화될 수 있습니다.
- 독립적으로 저장한 게임 템플릿은 같은 브라우저의 `localStorage` 키 `doitkit-game-templates`에 저장합니다. 다른 브라우저·기기에는 공유되지 않습니다.
- 고객 검토 링크는 동일 목업의 화면 이동입니다. 실제 고객 인증·권한 분리 기능을 제공하지 않습니다.
- 날짜 판단은 한국 시간(Asia/Seoul)을 기준으로 합니다. 자동 종료·예약 리포트 처리는 목업이 실행 중일 때 상태를 확인하는 방식이며 서버 예약 작업이 아닙니다.
- 시연 화면에는 가상 브랜드·담당자·성과 데이터를 사용합니다. 실제 개인정보를 입력하지 마세요.
- Google Fonts 등 외부 리소스 접근 여부에 따라 대체 폰트가 표시될 수 있습니다.

## 기능 검증

Node.js 20 이상을 권장합니다. 추가 패키지 설치 없이 저장소 루트에서 실행합니다.

```sh
node scripts/check.cjs
```

개별 검증은 아래처럼 실행합니다.

```sh
node checks/demo-regression.cjs
node checks/checkout-return-regression.cjs
node checks/billing-flow-regression.cjs
```

검증 코드는 가상 DOM과 상태 기반으로 실행하며, 화면의 실제 픽셀 배치나 모든 브라우저 동작을 검증하지는 않습니다. 수정 후에는 브라우저에서도 행사 등록 → 제작 → 검토 → 패스 활성화 → 게시 → 운영 → 종료 → 성과 흐름, 뒤로가기, 모달, 좁은 화면 배치를 확인하세요.

## 공동 수정

저장소 소스를 수정하려면 GitHub 저장소의 쓰기 권한이 필요합니다. 권한이 없으면 포크에서 수정하고 Pull Request로 제안할 수 있습니다. 공개 목업 사이트의 열람 권한과 이 GitHub 저장소의 수정 권한은 별개입니다.
